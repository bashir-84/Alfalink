# انتشار مستقیم روی GitHub Pages

این نسخه همان صفحهٔ پنج‌کارتی تأییدشده است: فونت Peyda، سه کارت در ردیف دسکتاپ، سه پروژه، دو ابزار و فیلتر دسته‌بندی. عکس‌ها و فونت داخل بسته‌اند. باز کردن index.html کنار بقیهٔ فایل‌ها برای دیدن نمونه کافی است.

## روش پیشنهادی: کارت‌های خودکار

۱. یک Repository عمومی جدید در گیت‌هاب بسازید و شاخهٔ اصلی را main نگه دارید.

۲. فایل ZIP را روی کامپیوتر Extract کنید. **همهٔ محتویات استخراج‌شده** را از Add file → Upload files در ریشهٔ مخزن آپلود کنید. خود فایل ZIP را آپلود نکنید. index.html باید مستقیم در صفحهٔ اصلی مخزن باشد، نه داخل یک پوشهٔ اضافی.

۳. پوشهٔ .github ممکن است هنگام آپلود مرورگری جا بیفتد. برای اطمینان، فایل `.github/workflows/pages.yml` باید در مخزن وجود داشته باشد. اگر نبود: Add file → Create new file؛ نام را دقیقاً `.github/workflows/pages.yml` وارد کنید؛ محتوای فایل `GITHUB-WORKFLOW.txt` داخل بسته را کپی کنید و Commit changes را بزنید. فایل GITHUB-WORKFLOW.txt فقط کپی کمکی برای همین مرحله است و خودش اجرا نمی‌شود.

۴. به Settings → Pages بروید و در بخش Build and deployment، گزینهٔ Source را روی **GitHub Actions** بگذارید.

۵. تب Actions را باز کنید؛ اگر لازم شد Actions را برای همین مخزن فعال کنید. گردش‌کار Publish site cards را انتخاب کنید و Run workflow را بزنید. گزینهٔ Refresh existing screenshots too را در بار اول خاموش بگذارید تا ظاهر عکس‌ها دقیقاً مثل نسخهٔ تأییدشده بماند.

۶. پس از سبزشدن مرحلهٔ deploy، لینک سایت در همان اجرا مشخص است. برای مخزن معمولی، قالب آدرس https://USERNAME.github.io/REPOSITORY/ است.

## افزودن کارت؛ فقط با لینک

در گیت‌هاب فایل links.txt را باز کنید و علامت مداد را بزنید. لینک جدید را زیر دستهٔ مربوط بنویسید:

```
[project]
https://example.com/project-one/

[tool]
https://example.com/tool-one/
https://example.com/tool-two/
```

لینک‌های قبلی را نگه دارید و لینک تازه را در خط جدید اضافه کنید. Commit changes را بزنید؛ فرایند انتشار خودکار اجرا می‌شود. سایت مقصد باید عمومی باشد. عنوان، توضیح و تصویر کارت جدید از همان سایت گرفته می‌شود. نیازی به ویرایش index.html یا ساخت کارت خالی نیست.

برای حذف یک کارت، خط لینک آن را پاک کنید. برای انتقال دسته، لینک را به زیر عنوان دستهٔ دیگر ببرید. ترتیب کارت‌ها از ترتیب لینک‌ها در هر دسته می‌آید. لینک تکراری فقط یک بار نمایش داده می‌شود. خط‌های خالی و خط‌هایی که با # شروع می‌شوند نادیده گرفته می‌شوند.

پیش‌نمایش‌ها ثابت‌اند. برای گرفتن عکس تازه از همهٔ سایت‌ها، در Actions → Publish site cards → Run workflow گزینهٔ Refresh existing screenshots too را روشن کنید. کارت‌های پنج‌گانهٔ اولیه از عکس‌های تأییدشدهٔ داخل بسته استفاده می‌کنند. عکس کارت‌های جدید هنگام هر اجرای ساخت دوباره تهیه می‌شود؛ داده‌های تولیدشده در همان انتشار نگهداری می‌شوند و به مخزن commit نمی‌شوند.

اگر سایت مقصد کپچا، ورود یا محدودیت دسترسی داشته باشد، ممکن است عکس تهیه نشود؛ خود کارت و لینک آن همچنان فعال‌اند. برای کارت‌های اولیه، عکس موجود در بسته به عنوان جایگزین حفظ می‌شود. نیاز به API key یا سرویس پولی عکس نیست؛ زمان و سهمیهٔ GitHub Actions تابع حساب گیت‌هاب شماست.

## روش ساده‌تر: فقط انتشار همین پنج کارت

اگر فعلاً کارت خودکار لازم ندارید، می‌توانید در Settings → Pages، Source را Deploy from a branch و سپس main و /(root) انتخاب کنید. همین فایل‌ها صفحه را نمایش می‌دهند. در این روش، ویرایش links.txt به‌تنهایی کارت جدید نمی‌سازد؛ ساخت خودکار فقط با روش GitHub Actions بالاست. این دو روش را با هم ترکیب نکنید.

## فایل‌ها

- index.html: ظاهر صفحه و عملکرد دسته‌بندی و کارت‌ها.
- catalog.js: اطلاعات اولیهٔ پنج کارت؛ برای روش خودکار نیازی به ویرایش آن نیست.
- assets/: تصاویر ثابت و فونت Peyda با فایل مجوز پیوست‌شده.
- links.txt: تنها فایل لازم برای افزودن لینک و تعیین دسته.
- scripts/build.mjs: تولید پیش‌نمایش‌ها و خروجی ثابت.
- .github/workflows/pages.yml: ساخت و انتشار خودکار.
- package.json و package-lock.json: وابستگی‌های ساخت؛ حذفشان نکنید.

## اجرای محلی برای توسعه (اختیاری)

با Node.js نسخهٔ ۲۲ و از پوشهٔ پروژه:

```
npm ci
npx playwright install chromium
npm run build
```

خروجی در پوشهٔ _site است. نصب ابزار برای بازدیدکنندگان لازم نیست. برای بازکردن نمونهٔ اولیه هم نیازی به این دستورات نیست.
